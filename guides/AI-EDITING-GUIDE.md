# AI로 수정하는 분을 위한 가이드

AI 코딩 도구로 디자인이나 동작을 바꾸는 사람을 위한 개발 가이드입니다. 화면에서 내용만 입력하려면 [HTML 사용자 가이드](HTML-USER-GUIDE.md)를 보세요.

## 먼저 읽을 파일

1. [AGENTS.md](../AGENTS.md): 작업 규칙과 푸시 전 확인 사항
2. [README.md](../README.md): 현재 저장·공개 방식과 개인정보 고지
3. [TODO.md](../TODO.md): 우선순위와 아직 확인하지 않은 작업

이 프로젝트는 GitHub Pages용 정적 HTML/CSS/JavaScript입니다. 별도 요청 없이 서버·DB·로그인 체계를 도입하지 마세요.

## 어떤 파일을 고칠까?

| 바꿀 내용 | 개발 원본 |
| --- | --- |
| 편집기 화면 뼈대·버튼·문구 | `templates/edit.html` |
| 하객용 화면 뼈대·로딩·비밀번호 창 | `templates/index.html` |
| 색·글자·레이스·모바일 배치 | `style.css`, `assets/` |
| 편집 기능·사진 보관함·저장 UI | `editor.js` |
| 초안 자동 저장 | `draft-store.js` |
| 페이지 종류·기본 샘플·사진 참조 | `content.js` |
| 페이지별 렌더링 | `render.js` |
| 하객용 데이터 선택·보호된 초대장 열기 | `guest.js` |
| 암호화·입력 데이터 검증 | `vault.js` |
| 참석 버튼·입력창 | `rsvp.js` |
| Google Sheets 접수 처리 | `integrations/google-sheets/` |
| 최종 HTML 생성 | `scripts/build-html.mjs` |

루트의 `index.html`과 `edit.html`은 원본을 묶은 생성물입니다. 생성물만 고치면 다음 생성 시 변경이 사라집니다. **원본을 수정한 뒤 HTML 두 개를 다시 생성하세요.**

편집기에서 저장한 실제 청첩장 `index.html`도 같은 이름일 수 있습니다. 사용자 데이터를 담은 배포 파일과 개발용 생성물을 구분하고, 기존 배포 파일을 덮어쓰기 전에 보존하세요. 빌더는 브라우저 초안을 가져오거나 실제 개인정보를 자동 삽입하지 않습니다.

## AI에게 요청하는 예시

```text
AGENTS.md, README.md, TODO.md와 guides/AI-EDITING-GUIDE.md를 먼저 읽어줘.
모바일 청첩장의 본문 글자와 여백을 조정해줘.
원본 파일을 수정하고 HTML을 다시 생성해줘.
브라우저 자동 저장과 사진 보관함, 페이지 삭제 시 사진 보존을 유지해줘.
실제 화면을 확인하고 검증한 범위와 미확인 사항을 알려줘.
푸시는 별도로 요청할 때만 해줘.
```

사진·계좌·개인 연락처 대신 가상 데이터를 예시로 제공하세요. 비밀번호와 Google/GitHub 인증 토큰을 프롬프트나 코드에 넣지 마세요.

## 수정하고 확인하기

개발자가 원본을 변경할 때는 Node.js가 필요합니다. 완성된 HTML을 사용하는 사람에게 Python·Node.js 설치를 요구하지 않습니다.

```sh
node scripts/build-html.mjs
node --test tests/*.test.mjs
```

변경과 관련된 검증을 하고, 화면을 바꿨다면 실제 브라우저에서 확인하세요. 테스트 통과를 실제 모바일 검수나 Google Sheets 저장 완료와 동일하게 보고하지 마세요. `file://` 열람을 검수 환경이 차단하면 그 한계를 기록하고 우회하지 마세요.

빌더는 CSS·JS·벡터 장식을 HTML 안에 넣고 CSP 해시를 맞춥니다. 저장된 공개용 HTML은 내부 데이터를 우선 읽으며, 개발용 하객 화면은 로컬 초안·기존 배포 데이터에 대한 호환 경로도 가집니다.

## 반드시 유지할 동작

- 입력 시 브라우저에 자동 저장하고, 실패를 성공으로 표시하지 않습니다.
- 자동 저장은 현재 브라우저 초안이며 공개 GitHub 파일을 자동 수정하지 않습니다.
- 편집창에는 새 청첩장이나 JSON 불러오기·내보내기 기능을 다시 넣지 않습니다. 저장 버튼 이름은 **저장**입니다.
- 페이지 삭제는 사진 보관함을 지우지 않습니다. 사진의 페이지 참조만 제거합니다.
- 사진 데이터는 공용 보관함에 두고 페이지에서는 ID로 참조합니다. 기존 형식의 사진을 읽는 호환도 유지합니다.
- 보호된 공개용 파일에 비밀번호·복호화 키를 포함하지 않습니다. 공개용 파일에는 사용하지 않는 보관 사진도 포함되므로 이를 숨긴 개인정보라고 취급하지 않습니다.
- 참석 응답 미리보기에서 실제 저장 성공을 표시하지 않습니다. 실제 시트 연결은 본인 계정 설정과 배포 후 확인이 필요합니다.
- 사용자의 기존 초안을 임의로 초기화하거나, 개인정보를 샘플·테스트·공개 커밋에 넣지 않습니다.

## 푸시와 공개

사용자가 푸시를 요청하면 변경·검증을 마친 뒤, **“index.html을 직접 열 수 있는 테스트 기능을 막을까요?”**라고 매번 확인합니다. 이미 해당 푸시에 대해 답변했다면 그 결정을 따르고 같은 질문을 반복하지 않습니다.

**현재 결정은 직접 열기 유지입니다.** 나중에 배포 전에 차단할 작업은 TODO에 남겨두었습니다. 차단은 로컬 열기 동작에 대한 정책일 뿐, 공개 저장소의 소스 열람이나 파일 다운로드를 막는 보안 기능이 아닙니다.

원본·생성물·문서가 일치하는지와 민감 정보 포함 여부를 확인한 뒤 커밋합니다. 사용자의 푸시 요청 없이 임의로 푸시하지 마세요.
