# HTML만 사용하는 분을 위한 가이드

코드를 수정하지 않고 화면에서 청첩장을 만드는 방법입니다. Python·Node.js 설치나 명령어 실행은 필요하지 않습니다.

## 준비할 것

- `edit.html`: 청첩장을 수정하는 화면
- 웹 브라우저: 평소 쓰는 같은 브라우저로 계속 작업하세요.
- 이름, 예식 정보, 사진 등 넣을 내용

`index.html`은 하객에게 보여주는 화면입니다. 내용을 수정할 때는 `edit.html`을 여세요.

## 1. 편집하고 자동 저장하기

1. `edit.html`을 더블 클릭하거나 제공받은 편집 화면 주소를 엽니다.
2. **기본 정보 · 디자인**에서 이름, 날짜, 분위기를 정합니다.
3. **디자인 템플릿**에서 준비된 디자인의 미리보기를 보고 **적용**을 누릅니다. 이름·사진·페이지 구성은 유지됩니다. 템플릿을 직접 만들거나 파일로 올리는 기능은 없습니다.
4. **페이지 추가**로 필요한 내용을 넣고, 각 페이지를 선택해 입력합니다.
5. 위·아래 버튼으로 순서를 바꾸고 오른쪽 미리보기를 확인합니다.
6. **자동 저장됨**이 표시되는지 확인합니다.

입력할 때마다 현재 브라우저에 자동 저장됩니다. 다시 수정하려면 **같은 브라우저에서 같은 파일 위치 또는 같은 주소**를 여세요. 직접 열기 테스트 기능은 현재 켜져 있으며, 브라우저 정책에 따라 로컬 자동 저장이 제한될 수 있습니다. 저장 실패 안내가 나오면 그대로 창을 닫지 마세요.

자동 저장은 현재 기기의 초안 보관입니다. 다른 기기·브라우저로 옮겨지거나 공개 사이트에 바로 반영되지는 않습니다. 시크릿 모드, 사이트 데이터 삭제, 파일 위치 변경은 피하세요.

## 2. 사진과 페이지 다루기

사진 페이지에서 사진을 추가하면 **사진 보관함**에도 저장됩니다. 다른 사진 페이지에서도 보관한 사진을 골라 쓸 수 있습니다.

- **페이지 삭제:** 페이지 구성만 삭제합니다. 사진은 보관함에 남습니다.
- **페이지에서 빼기:** 그 페이지에서만 사진을 뺍니다. 보관함에서는 지우지 않습니다.
- **기본 정보 · 디자인 → 사진 보관함:** 보관된 사진을 확인합니다.

공개용 청첩장 파일에도 보관 사진이 포함됩니다. 현재 페이지에 보이지 않는 사진도 포함되므로 공개 전에 확인하세요.

## 3. 저장하고 공유하기

자동 저장과 하객에게 전달할 파일 저장은 다릅니다.

1. **저장**을 누릅니다.
2. **비밀번호로 보호하기** 또는 **누구나 열 수 있게 공개하기**를 선택합니다.
3. 비밀번호로 보호한다면 12자 이상의 비밀번호를 정하고 확인합니다.
4. 창 안의 **저장**을 눌러 `index.html`을 받습니다.
5. 받은 파일을 열어 최종 내용을 확인합니다. 파일 이름이 `index (1).html`처럼 바뀌었다면 배포할 때는 `index.html`로 정리합니다.
6. GitHub Pages 배포 폴더의 `index.html`을 이 파일로 교체하고 업로드합니다. GitHub 작업이 어렵다면 배포를 맡은 사람에게 이 파일을 전달하세요.

비밀번호를 설정한 경우 링크와 비밀번호를 따로 전달하세요. 비밀번호가 없는 파일은 저장소에서도 내용을 읽을 수 있습니다. 비밀번호는 복구할 수 없습니다.

받은 `index.html`은 열람·배포용입니다. 이것만으로 다른 브라우저의 편집 초안을 복구하는 기능은 현재 없습니다. 수정에 사용하던 브라우저의 데이터를 지우지 말고, 공개용 파일도 별도로 보관하세요.

## 4. 참석 의사 받기

청첩장 안에서 참석 입력창을 띄우는 기능은 준비되어 있습니다. 실제 Google Sheets 저장은 본인 계정에서 최초 연결이 필요합니다.

[Google Sheets 연결 안내](../integrations/google-sheets/README.md)를 따라 접수 주소를 만들고, 편집 화면의 **참석 의사 → Google Sheets 접수 주소**에 넣으세요. 시트의 편집 링크를 넣는 항목이 아닙니다.

최초 연결이 어렵다면 연결을 맡은 사람에게 도움을 요청하세요. 연결 후에는 시트만 열어 응답을 확인하면 됩니다. 연결 전·편집기·로컬 테스트의 입력창은 미리보기이며 실제로 저장하지 않습니다. HTTPS로 배포한 청첩장에서 응답 한 건을 보내 확인하세요.

## 자주 헷갈리는 점

| 상황 | 확인할 것 |
| --- | --- |
| 수정했는데 하객 화면은 그대로예요 | 자동 저장만으로 공개 파일이 바뀌지는 않습니다. **저장**으로 새 파일을 받아 배포 파일을 교체하세요. |
| 다시 열었는데 입력 내용이 없어요 | 같은 브라우저·같은 파일 위치/주소인지, 사이트 데이터를 삭제했는지 확인하세요. |
| 사진 페이지를 삭제했어요 | 기본 정보의 사진 보관함을 확인하고 새 사진 페이지에서 다시 담으세요. |
| 참석 응답이 시트에 없어요 | 접수 주소 연결 및 Google 배포를 확인하세요. 로컬 테스트는 실제 저장을 하지 않습니다. |
| 저장 실패라고 나와요 | 브라우저의 저장 공간·사이트 저장 허용 여부를 확인하세요. 다른 브라우저로 옮기기 전에 현재 내용과 사진을 보존하세요. |

개인정보 공개 범위와 책임 고지는 [README](../README.md)의 **공개와 암호화**, **개인정보 보호 및 책임 고지**를 확인하세요.
