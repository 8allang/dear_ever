# Google Sheets 최초 연결

이 폴더는 Google 계정에서 최초 한 번 연결할 때 사용합니다. 하객은 청첩장 안에서 참석 입력을 끝냅니다. 하객에게 시트 공유 권한이나 Google 로그인은 필요하지 않습니다 (개인 Google 계정에서 공개 웹 앱 배포를 허용하는 경우).

1. https://script.google.com/ 에서 새 프로젝트를 만듭니다.
2. 기본 `Code.gs` 내용을 이 폴더의 `Code.gs`로 교체합니다.
3. **+ → HTML**을 선택해 `Form`이라는 파일을 만들고 `Form.html` 내용을 붙여넣습니다.
4. 상단 실행 함수로 `setup`을 선택해 실행하고, 본인 Google 계정에서 시트 생성 권한을 승인합니다. 실행 로그에 표시되는 시트 URL을 보관하세요. 기본 시트는 비공개로 유지합니다.
5. **배포 → 새 배포 → 웹 앱**을 선택합니다. **실행 사용자: 나**, **액세스: 모든 사용자**로 설정해 배포합니다. 조직 계정 정책에 따라 이 옵션이 제한될 수 있습니다.
6. `/exec`로 끝나는 웹 앱 URL을 복사합니다. **시트 URL이나 `/dev` 테스트 URL이 아닙니다.**
7. 청첩장 `edit.html`의 **참석 의사 → Google Sheets 접수 주소**에 붙여넣습니다. 입력은 자동 저장됩니다.
8. 공개용 청첩장 HTML을 저장해 GitHub Pages에 반영하고, 실제 링크에서 테스트 응답 한 건을 보내 시트에 기록되는지 확인합니다. 배포본 변경 시 Apps Script에서도 새 버전 배포를 갱신하세요.

로컬에서 HTML을 직접 열거나 편집기 미리보기에서는 입력 UI만 확인하며, 실제 응답을 저장했다고 표시하지 않습니다. 실제 시트 연결 테스트는 GitHub Pages의 HTTPS 주소에서 진행합니다.

응답은 Script 소유자 권한으로 고정된 시트에 추가됩니다. 시트 ID나 접수 받을 시트를 하객 요청에서 받지 않으며, 기존 응답을 읽는 공개 API는 제공하지 않습니다. 입력 검증·수식 주입 방지·같은 요청 ID 재전송 중복 방지·간단한 봇 입력 함정을 포함합니다. 공개 접수 주소에는 임의 제출이 가능하므로 강한 스팸 방지나 무제한 처리를 보장하지 않습니다. Google Apps Script 사용량 제한이 적용됩니다.

iframe을 허용하기 위해 ALLOWALL을 사용합니다. 입력창에는 접수 기능만 제공하고, 관리/읽기/권한 변경 기능을 추가하지 마세요. 예식 후에는 응답을 정리하고 웹 앱 배포를 중단하세요.
